# Dota 2 Match Coach

[English](README.md) | [Русский](README.ru.md)

Агентский скилл для доказательного разбора матча Dota 2 текущего патча по `match_id`. Игрок выбирается по `account_id` или точному английскому имени героя. Перед тренерской интерпретацией встроенный runtime собирает OpenDota, STRATZ и официальный Valve patch timeline, нормализует данные с provenance и открывает только подтверждённые data gates.

Проект ориентирован только на последний точный подпатч. Старые или не подтверждённые по Valve timeline матчи не создают success-артефакт.

## Возможности

- parse-first сбор OpenDota с сохранением базового scoreboard при недоступном replay;
- STRATZ GraphQL с обязательным `User-Agent: STRATZ_API`;
- проверка последнего точного подпатча через Valve timeline;
- Radiant/Dire draft, lane outcome, итоговые метрики, покупки и инвентарь;
- четыре стадии матча, временные ряды и extrema внутри матча; каждое поминутное значение привязано к записанному времени отсчёта реплея;
- поминутная разница команд по заработанному золоту, опыту и, если он записан, net worth: изменения по стадиям, смены лидера и крупнейшие перепады;
- записанные объекты (здания, Рошан, Аегис, Торментор, первая кровь, курьеры), установка вардов, байбэки и порядок прокачки;
- механики текущего патча из Valve datafeed: способности, значения и таланты выбранного героя, способности остальных героев, купленные предметы и патчноуты текущего подпатча по ним, чтобы разбор объяснял способности и предметы без опоры на память модели;
- allowlisted timeline событий и teamfights с проверкой границ duration;
- скачки позиции с подписанной причиной: вход в перенос союзника не читается как одиночный телепорт;
- явные source conflicts с сохранением альтернатив и provenance;
- детерминированные JSON/Markdown-артефакты и безопасные CLI-ошибки;
- PowerShell и POSIX wrappers без npm-зависимостей;
- выбор игрока по точному английскому имени героя для разбора чужих матчей;
- автоматический русский или английский язык полного тренерского ответа.
- полный, краткий и тематический разбор с упражнением, связанным с главным выводом;
- сравнение личного прогресса по сохранённым сопоставимым матчам текущего подпатча;
- защита сравнений от неполного списка смертей и пропусков отдельных метрик в выборке.

Глубокий разбор сырого `.dem` намеренно не входит в runtime v1: без него нельзя достоверно объяснять каждый input или пропущенного крипа. Baseline, который собирает runtime, — это выборка того же героя, позиции и bracket на текущем патче, и она даёт среднее с размером выборки, а не перцентиль.

Статистическая модель пика, расширенные распределения и baseline сильных игроков, а также глубокий `.dem`-анализ зафиксированы в [ROADMAP.md](ROADMAP.md). Личный прогресс по сохранённым нормализованным матчам уже доступен.

## Требования

- Node.js 18+;
- сетевой доступ к OpenDota, STRATZ и Valve;
- PowerShell на Windows либо POSIX `sh` на macOS/Linux;
- рекомендуемый `STRATZ_API_KEY` для STRATZ position/lane/playback enrichment.

`npm install` и `package.json` не нужны.

## Установка

Установите скилл глобально через [Vercel Skills](https://github.com/vercel-labs/skills). CLI предложит выбрать, в какого обнаруженного агента или агентов его добавить:

```sh
npx skills add atlonis/dota2-coach-skill --skill dota2-match-coach --global --copy
```

Проверьте установку:

```sh
npx skills list --global
```

После установки откройте новую сессию выбранного агента и попросите:

```text
Используй $dota2-match-coach и разбери матч 8963363814 для account_id 56386500.
```

Для чужого матча можно выбрать игрока по герою:

```text
Используй $dota2-match-coach и разбери игрока на Earth Spirit в матче 8963363814.
```

Скилл сам выберет платформенный runtime, соберёт данные и проверит независимые data capabilities до начала разбора. Для расширенных position/lane/playback данных задайте `STRATZ_API_KEY` в среде выбранного агента. Токен нужен и для peer baseline, но не гарантирует его: должны быть известны позиция и ранг — медаль самого игрока либо средний bracket матча как запасное основание и хотя бы одна неделя целиком внутри текущего патча. Настройка токена, schema, exit codes и troubleshooting описаны в [runtime contract](dota2-match-coach/references/runtime.md). Не добавляйте токен в запросы, команды, файлы проекта или Git.

## Язык ответа

Полный пользовательский ответ следует языку пользователя: русский запрос даёт русский разбор, английский — английский. Явное указание языка имеет приоритет; в смешанном диалоге используется язык последнего содержательного сообщения.

Локализуются заголовки, таблица стадий, ограничения данных, уведомления об источниках и упражнение. Названия героев и предметов сохраняются в написании источника. Внутренние ключи схемы, имена capabilities и коды ошибок остаются в артефактах доказательств, а не в тренерском тексте.

## Объём разбора и личный прогресс

Можно запросить полный разбор, краткий ответ или отдельную тему: например, предметы или добивания к десятой минуте. Главный вывод выбирается по запросу, качеству доказательств и возможности предложить полезное действие. Повторяющиеся обстоятельства смертей не получают автоматического приоритета над вопросом игрока. Число тренировочных повторов можно предлагать как план; игровые нормативы требуют подходящего сравнения с источником.

Для сравнения с ранее сохранёнными разборами того же игрока:

```sh
./dota2-match-coach/scripts/analyze-match.sh MATCH_ID ACCOUNT_ID --history-dir ./dota2-match-coach/output --output-dir ./dota2-match-coach/output
```

В PowerShell используется параметр `-HistoryDir` вместе с существующими именованными параметрами. Для личного среднего нужны минимум два разных предыдущих матча на том же герое, позиции, в том же режиме и текущем точном подпатче. Размер выборки считается отдельно для каждого показателя. Используются сохранённые нормализованные JSON-артефакты; автоматического сбора истории аккаунта нет. Разница описывает эти матчи и не доказывает эффект тренировки. Подробнее — [личный прогресс](dota2-match-coach/references/progress.md).

## Data capabilities

Runtime записывает независимые `dataQuality.capabilities`:

- `scoreboard` — доступны базовые факты матча;
- `phaseAggregates` — доступны наблюдаемые фазовые метрики;
- `draft` — известны пять героев Radiant и пять Dire;
- `peerBaseline` — доступна выборка того же героя, позиции и bracket на текущем патче;
- `selectedTimeline` и `allPlayerPositions` — доступны необходимые playback timelines;
- `deathContext` и `deathPattern` — доступны полные контексты смертей или повторённая подтверждённая сигнатура;
- `teamEconomy` и `objectiveTimeline` — доступны поминутная разница команд и записанные объекты;
- `wardPlacements`, `buybackLog` и `skillBuild` — доступны соответствующие логи выбранного игрока;
- `currentMechanics` — доступны механики текущего патча для выбранного героя;
- `currentPatch` — подтверждён последний точный подпатч.

Значение false запрещает только соответствующий тип вывода. `deathPattern: false` означает, что подтверждённое повторение не выделено; перед выводом об отсутствии повторения нужно проверить полноту данных о смертях.

## Проверка

Из корня репозитория:

```sh
node --test test/runtime/*.test.mjs dota2-match-coach/scripts/test/*.test.mjs
```

Объединённый suite содержит репозиторные регрессии и v2-тесты скилла. Сеть не требуется, пока не заданы переменные opt-in live smoke. Платформенные и неактивные live-тесты штатно пропускаются.

Итоговый тренерский ответ дополнительно проверяется через [сценарии для независимого агента](test/coaching/README.md): неполный replay, ноль смертей, несовпадение рангов и узкие вопросы. Это отдельная проверка, она не входит в Node suite.

## Политика источников

OpenDota служит основным источником match object и parse job; STRATZ добавляет position/lane/playback enrichment; Valve подтверждает точный текущий подпатч, а его datafeed даёт механики текущего патча. Dota2ProTracker, старый Fandom и Valve `GetMatchDetails` не являются runtime-зависимостями. Полные правила находятся в [source policy](dota2-match-coach/references/source-policy.md).
